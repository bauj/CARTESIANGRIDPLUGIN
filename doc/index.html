Cartesian Grid plugin

3D algorithm Cartesian Grid 3D meshes a volume shape with an axis-aligned Cartesian grid of hexahedra (staircase cells). Each cell belongs to the smallest solid containing its center (a point on a face counts as inside), so nested or overlapping solids (GDML World Volumes) work: the deepest volume wins.

Hypothesis Cartesian Grid Parameters

  • Per axis X, Y, Z (one tab per axis in the dialog), one of:
    • Nb cells n: spacing = extent / n;
    • Step s: n = max(1, round(extent / s)), spacing adjusted so the grid covers the bounding box exactly;
    • Coordinates: absolute node coordinates (sorted list, at least 2 distinct values; in the dialog: the list starts with the bounds of the shape, Insert adds the selected value plus the insert step, Copy puts the selected values (or all) in the clipboard, Paste adds numbers copied from another axis, a text file or a spreadsheet; Ctrl+C / Ctrl+V on the list, several values selected with Ctrl or Shift + click). The grid spans the first to the last value along that axis, whatever the bounding box: parts of solids beyond it are not meshed (warning);
    • Spacing: spacing functions f(t), as in Body Fitting (in the dialog: table of ranges From t, To t, f(t); Insert splits the selected range, Delete merges it). Internal points, between 0 and 1, split the bounding box into ranges; t runs from 0 to 1 within each range. At most about 1000 cells per range between internal points; add internal points for finer grids.
    The extent is the tight bounding box of the solids. Modes can differ between axes.
  • Cells outside all solids: Remove (default) or Keep. Kept cells are bound to the main shape, which must then be a compound; a warning gives their number.

Materials

Create solid groups on the geometry (in SHAPER GDML mode: Create material groups gives MAT_<material> groups), then tick Create all groups on geometry in the mesh dialog: one mesh group per material.

Cartesian Grid Wizard

Mesh > SMESH plugins > Cartesian Grid Wizard goes from a geometry to the Cartesian MED file in one dialog, without the Create Mesh steps:

  • Geometry: the dialog is not modal; while its selection button is pressed, the field follows the GEOM or SHAPER geometry selected in the object browser.
  • Mesh: the meshes of that geometry using the Cartesian Grid 3D algorithm, plus New mesh. The chosen mesh is updated; a new mesh gets the algorithm and a Cartesian Grid Parameters hypothesis and stays in the study as an ordinary mesh.
  • Grid: the same per-axis tabs as the hypothesis dialog, filled from the chosen mesh.
  • Export: MED file and zone prefix; zones come from the geometry groups.
  • Also compute the SMESH mesh (optional): computes the hexahedra and creates one mesh group per geometry group of solids (names already used are skipped, groups of faces or edges are skipped). A SMESH mesh is unstructured: every node and hexahedron is stored, so it is much bigger and slower than the Cartesian MED file. It is only needed to view the cells.

Run shows a progress bar (export, then compute) and a Cancel button, then a summary. The MED file is written first: a failed or canceled compute leaves it, with a warning in the summary. The dialog stays open for another run. Changing the grid of a computed mesh clears its cells until it is computed again.

The dialogs, the wizard, its summary and its own errors follow the SALOME language (English or French); as in the other SMESH plugins, errors coming from the mesher engine (compute errors, grid validation, export errors) are in English.

Cartesian MED export

Run from Mesh > SMESH plugins > Cartesian Grid Wizard (below), or from Python with ExportCartesianMED: the grid is written to a MED file as a Cartesian mesh (three coordinate arrays, one zone per cell), far smaller than an unstructured export. A summary gives the cells per zone.

  • Zones from the geometry (wizard, Python source="geometry", no mesh element needed): zones are the geometry groups of the main shape whose name starts with the zone prefix (MAT_ by default, empty: all groups); a cell takes the zone of the solid containing its center. A solid in two zone groups is an error; solids in no zone group are listed in the summary. Without any zone group the file holds the grid only (every cell in family 0) and the summary starts with a warning.
  • Zones from the mesh (Python only, source="mesh"): zones are the volume groups of the computed mesh whose name starts with the prefix. A cell in two zone groups is an error.
  • File: one Cartesian mesh named after the mesh, components X, Y, Z, cells numbered i fastest, then j, then k. Family 0: no zone; zone groups sorted by name get families -1, -2, ... named FAM_<group>, each holding the group. Group names: at most 60 characters.
  • Solver reading (MED C library): MEDmeshInfo, MEDmeshGridIndexCoordinateRd per axis, MEDmeshEntityFamilyNumberRd on MED_CELL/MED_HEXA8, MEDnFamily and MEDfamilyInfo for the group names. Read zones by group name and accept families holding several groups (planned for mixed cells).
  • SMESH (File > Import > MED) and ParaVis open the file; SMESH shows the group names padded with spaces.

Python

mesh = smesh.Mesh(shape)
algo = mesh.CartesianGrid()
hyp = algo.Grid(nbCells=[40, 40, 20])   # or step=2.5, keepOutsideCells=True
hyp.SetStep(2, 5.0)                     # axis 0=X, 1=Y, 2=Z
hyp.SetCoordinates(0, [0, 2, 5, 10])    # X node coordinates
hyp.SetSpacing(2, ["0.5", "2"], [0.5])  # Z: 0.5 up to the middle, then 2
# same two lines in one call:
# algo.Grid(coordinates=[[0, 2, 5, 10], None, None], spacing=[None, None, (["0.5", "2"], [0.5])])
mesh.Compute()
algo.ExportCartesianMED("grid.med", source="geometry", zonePrefix="MAT_")   # returns the summary (English)
# the summary as messages [(key, args)], keys of CartesianGridPluginBuilder.REPORT_FORMATS:
# CartesianGridPluginBuilder.ExportCartesianMEDMessages(mesh, "grid.med")

Limits

  • The algorithm must be assigned to the main shape (all solids); no sub-meshes.
  • Every solid must be closed. Solids smaller than a cell may own no cell (warning).
  • Memory: about 760 bytes per hexahedron (nodes included) in the SMESH process; a 100x100x100 box (106 cells) computes in about 1.6 s on 12 threads, a sphere in a 150x150x150 grid in about 3 s. Evaluate gives the exact node and hexahedron counts before computing.
  • Cells are classified in parallel on all cores, one line intersection per row of cells and per solid (exact point classification near the boundary only); nodes and hexahedra are then created on one thread. The compute shows its progress and can be canceled, leaving no partial mesh.
  • The plugin does not limit the number of cells, the memory does: about 16 bytes per cell for the Cartesian MED export alone, about 760 bytes per hexahedron for an SMESH mesh. A step giving more than 231 cells along an axis is refused.
  • A cell center the geometry kernel cannot locate in a solid is taken as outside it; a warning gives their number.
